# ファイル (エクスプローラ・SPEC・表示)

[overview.md](overview.md) から分けた、ファイルメニューのツリーとファイルの表示。検索は [search.md](search.md)。実装は `web/src/server/files.ts`。

## 1. ファイルメニューのサイドパネル

上から「検索欄」「SPEC」「EXPLORER」の順に並べる。SPEC と EXPLORER は境界線のドラッグで縦幅を変えられ、見出しのクリックで折りたためる ([ui.md](ui.md) §5)。

```
 [🔍 内容で絞り込む      ]
 ▾ SPEC (4)
     ▾ agent-tasks/feature/33_new_region
         spec.md
         plan.md
 ───────────────────
 ▾ EXPLORER            [変更のみ][.md のみ][gitignore]
     ▸ .devcontainer
     ▸ app …
```

### 1.1 エクスプローラ

- ツリー表示。比較対象との差分の状態 (M / A / U / D / R) を色と記号で示す ([git.md](git.md) §3)
- 子が 1 つしかないディレクトリは連結して表示する。並びはディレクトリが先、それぞれ名前の順
- `.gitignore` で無視されたファイルは表示しない
- 見出しの右の「変更のみ」「.md のみ」「gitignore」で絞り込む (組み合わせられる)
  - 変更のみ: 比較対象との差分があるファイルだけ (COMPARE に出るファイルと一致する)
  - gitignore: 無視されたファイルも薄い色で表示する。検索の対象にも含める
- 絞り込んでいる間 (検索を含む) はディレクトリをすべて開いて表示する
- 最初はすべて閉じている。開閉と絞り込みは保存しない
- フォーカスしているエディタグループで開いているファイルの行を、ホバーと見分けられる色 (水色) で示す。SPEC の行も同じ
  - 開いているファイルが変わると、エクスプローラでその親のディレクトリを開き、行が見えるまでスクロールする (開いたディレクトリはそのまま残す)
- ファイルが多すぎる (10 万件を超える) ときは一部だけ表示し、「除外パターンを追加してください」と出す

### 1.2 SPEC

- AI が作る設計資料 (spec / plan など) を、エクスプローラの上に常に表示する。表示はツリーだけ
- worktree バーの SPEC 欄で指定した場所にある `.md` を出す。`.gitignore` で無視されていても出す (除外パターンに当たるものは出さない)
- SPEC 欄が空のときは入力を促す案内、指定した場所に `.md` がないときは「指定した場所に .md はありません」を出す
- 検索では絞り込まない
- AI の作業ファイルは git の管理外なので、Git メニューの差分やエクスプローラの「変更のみ」には出ない

### 1.3 ツリーの右クリックメニュー

SPEC・エクスプローラ・Git メニューの変更ファイルのツリーで共通。

- 行を右クリックすると「相対パスをコピー」を出し、右クリックした行を枠で示す。コピーしたら右下に「コピーしました」
- ファイルの行では「ダウンロード」も出す。作業ツリーの今のファイルを、元のファイル名でダウンロードする (`GET …/raw?path=&download=1`。[security.md](security.md) §5)
  - ディレクトリの行と、Git メニューで削除 (D) になったファイルの行には出さない (作業ツリーにないため)
  - エクスプローラに残っている Unstaged の削除のファイルは、ダウンロードに失敗する (ブラウザのダウンロードの一覧に失敗と出る)
- 連結して 1 行で表示しているディレクトリは、その行が表す一番深いディレクトリのパスをコピーする
- 行以外の場所ではブラウザ標準のメニュー。メニューはツリー全体で 1 つだけ持つ

## 2. SPEC 欄の解釈と探し方

- 入力はカンマ区切り。各項目の先頭の `./` を取る
  - 末尾の `/*` は `/**` (その下すべて)
  - ワイルドカードのない、`.md` で終わらない指定はディレクトリとみなし `/**` を付ける
  - それ以外は glob (`**` と `*`) のまま
- パターンごとに、ワイルドカードより前のディレクトリ (`agent-tasks/feature/x/*` なら `agent-tasks/feature/x`) から `fs.readdir` でたどる
  - `.gitignore` に関係なく読む。除外パターンと別の worktree は除く。シンボリックリンクはたどらない
  - `.md` で、パターンに当たり、除外パターンに当たらないものを返す
  - 5,000 件、またはたどったディレクトリが 2 万個で打ち切る
- 入力は worktree ごとに保存する ([storage.md](storage.md))

## 3. 除外パターンと、表示・検索の対象

- **除外パターン**: エクスプローラ・SPEC・検索のどれにも出さない。「gitignore」を ON にしても出さない。`.gitignore` の書き漏れを補い、大量のファイルでツリーが重くなるのを防ぐ
  - 全体の設定の値に、プロジェクトの設定の値を追加したものを使う
  - 全体の設定の初期値: `**/node_modules/**`, `**/__pycache__/**`, `**/*.pyc`, `**/.venv/**`, `**/.terraform/**`, `**/.git/**`
  - パターンは worktree の直下から数える glob。`**` は 0 個以上のディレクトリ、`*` はディレクトリをまたがない任意の文字列 (`web/src/lib/glob.ts`)。ディレクトリのパスにも当てる (`dir/**` は `dir` 自体も外す)
- **worktree の中にある別の worktree** は、除外パターンに自動で足す (その worktree のパスと `<パス>/**`)。別のタブで開くため
- **列挙の時点で効かせる**: 除外パターンを git の pathspec `:(exclude,glob)<パターン>` と rg の `-g !<パターン>` にも渡し、余計なファイルを列挙させない。ただし pathspec はファイルに当てはめるもので、`--directory` が出すディレクトリの行には効かないので、最後に `glob.ts` の `matchesAny` でもう一度絞る。**正は glob.ts**

## 4. 一覧の作り方 (大きなリポジトリの扱い)

- 「gitignore」OFF: 管理下のファイルと Untracked
  - `git ls-files --cached --others --exclude-standard --deduplicate -z -- . <除外の pathspec>`
- 「gitignore」ON: 上に、無視されたものを足す
  - `git ls-files --others --ignored --exclude-standard --directory --no-empty-directory -z -- . <除外の pathspec>`
  - `--directory` で、無視されたディレクトリは `node_modules/` のように 1 行にまとまる (無視されたファイルが 12 万件あるリポジトリでも 39 行・0.01 秒)。これを中身を読んでいない (`lazy`) ディレクトリとして返し、開いたときに `fs.readdir` で読む (除外パターンと別の worktree を除き、シンボリックリンクはたどらない。中身はすべて無視されたもの)
  - `--directory` の出力にはディレクトリとその中の行が両方出ることがある (`**/.terraform/*` のように中身だけを無視するパターン)。lazy のディレクトリの下にある行は捨てる
  - 別の worktree を含む無視されたディレクトリ (`.worktree/`) は lazy にせず、その場で中身を読む。中身がすべて別の worktree なら、空のディレクトリとして消える
- Untracked の入れ子のリポジトリ (`dir/` の形で出るもの) は lazy のディレクトリにする
- サーバーでパスの一覧を木 (`FileNode[]`) にして返す。上限は 10 万件
- Unstaged の削除 (作業ツリーにない管理下のファイル) はツリーに出たまま、開くと「ファイルが見つかりません」になる。Staged の削除 (`git rm`) は `ls-files --cached` に出ないので、ツリーには出ない (Git メニューには出る)

## 5. ファイルの表示

- **Markdown**
  - GFM (表、タスクリスト)、mermaid、画像 (相対パス) に対応する
  - mermaid の図は、本文の幅に収まるように縮めて表示する (元の大きさより広げない)
  - mermaid の図と画像は、クリックすると画面の大きさ (幅 95vw・高さ 90vh) のモーダルで開き、拡大・縮小できる (§5.2)
    - リンクの中の画像 (バッジなど) は、クリックするとリンクを開く (モーダルは開かない)
    - 上の帯の左に、画像なら代替テキスト (なければファイル名)、図なら「Mermaid」を出す
    - 開いたときは、全体が枠に収まる倍率で中央に置く (小さなものは引き伸ばす)
  - 横幅は、表示している領域 (グループ) の幅いっぱい。最大の幅は決めない
  - 文字の大きさは全体の設定のフォントサイズ ([ui.md](ui.md) §3)。見出し・余白・中のコードブロックもそれに比例する
  - 相対リンクは、そのファイルのディレクトリを基準に解決して、アプリ内のタブで開く (`./plan.md`、`../../docs/adr/…`。`/` で始まるものは worktree の直下から。`#見出し` と `?…` は取り除く)
  - `#見出し` だけのリンク (目次など) は、同じプレビューの中の見出しへスクロールする。ブラウザの別のタブは開かず、URL も変えない
    - 見出しの名前は GitHub と同じ作り方 (小文字にし、文字・数字・`_`・`-`・空白以外を消して、空白を `-` にする。同じ名前は 2 つ目から `-1`, `-2` を付ける。`web/src/lib/slug.ts`)。画面のほかの id とぶつからないよう、見出しの `data-heading-id` に入れる
    - 見出しに当たらなければ、同じ id の要素 (GFM の脚注の `#user-content-fn-1` など) へスクロールする
  - `http(s):` と `mailto:` のリンクは、ブラウザの別のタブで開く
  - 画像の相対パスも同じく解決し、`GET …/raw?path=` で読む。`http(s):` と `data:` はそのまま
  - プレビューとソースを切り替えられる (パスのバー。下の「パスのバーの切り替え」)。検索結果から行を指定して開いたときはソースで開く
  - ソースはコードと同じく Markdown としてシンタックスハイライトする (見出しと強調は太字、リンクは下線、中のコードブロックはその言語で色を付ける)
- **HTML** (`.html` / `.htm`)
  - プレビューとソースを切り替えられる (既定はプレビュー)。プレビューは「全体」のときだけ。「差分」ではソースの差分を出す
  - プレビューは sandbox の iframe で開き、`GET …/preview/<合言葉>/<path>` でページを読む。スクリプトは動くが、sherpa と別の origin になり、sherpa の API は読めない ([security.md](security.md) §6)
  - 相対パスの CSS・画像・スクリプトとリンクは、同じ worktree のファイルとして読む。`/` で始まるパスは worktree の直下ではなく sherpa のサーバーの直下を指すので、読めない
  - ファイルの変更を検知して読み直したら、プレビューも開き直す
  - 地は白 (ダークのときも)。ページの中は `Ctrl+F` の検索の対象外 (別の origin なので中を読めない)
- **コード**: シンタックスハイライト (ブラウザで shiki)、行番号。色に加えて、テーマが決める太字・斜体・下線も効かせる。文字の大きさは全体の設定のフォントサイズ (差分の表示も同じ)。検索結果から開いたときは、その行へスクロールして強調する
- パンくずリストの横のボタンで相対パスをコピーする (コピーしたらアイコンを ✓ に変える)
- パスのバーの切り替え: パンくずリストの右に、ボタンを並べた組を 3 つと「History」を置く。選んでいるボタンを塗る。ファイルのタブと差分のタブ ([git.md](git.md) §2) で同じ
  ```
  [プレビュー|ソース] [Unified|Split] [差分|全体] [🕘 History]
  ```
  - `プレビュー|ソース`: Markdown と HTML のときだけ出す (HTML は「全体」のときだけ)。Markdown では「差分」のときも効き、プレビューならプレビューの差分、ソースならソースの差分を出す ([git.md](git.md) §6.1)
  - `Unified|Split`: 「差分」のときと、履歴で選んでいるときだけ出す。プレビューの差分も Unified / Split で出せる
  - `差分|全体`: ファイルのタブでは、比較対象との差分があるファイルのときと、履歴で選んでいるときだけ出す。「差分」はファイル全体に差分を重ねて表示する (変更のない行も省略しない)。差分のときは、パンくずリストの横に比較元 (`main...作業ツリー` など) を出す
  - `History`: 左にファイルの履歴を開き、選んだコミットの差分を本文に出す ([git.md](git.md) §8)
  - 既定は、ファイルのタブは「全体」、差分のタブは「差分」。どちらも Unified、プレビュー (行を指定して開いたときはソース)
  - 選んだものはエディタグループごとに持ち、同じグループのタブで共有する (タブを切り替えても同じ表示のまま)。分割して作ったグループは元のグループの選択を引き継ぎ、ほかのグループへ移したタブは移した先の選択に従う。検索結果の行から開いたときは、行を見せるため、そのグループを「全体」「ソース」にする
  - 保存はレイアウトと一緒 (`ws:<タブの id>`。[ui.md](ui.md) §8)

### 5.1 画像・バイナリ・大きなファイル

| 種類 | 判定 | ファイルのタブ | 差分 |
| --- | --- | --- | --- |
| 画像 | 拡張子 (`png` `jpg` `jpeg` `gif` `webp` `svg` `ico` `bmp` `avif`) | 拡大・縮小できる表示で開く (§5.2)。上の帯に大きさ (幅 × 高さ) とファイルのサイズを出す | 前後の画像を左右に並べる |
| バイナリ | 先頭 8 KB に `\0` がある (git と同じ判定) | 「バイナリのため表示しません (サイズ)」 | 「バイナリのファイルが変更されています」 |
| 大きなテキスト | 1 MB 超、20 万文字超、5,000 行超のどれか | ハイライトせず、行番号だけで表示し、その旨を出す | [git.md](git.md) §6 |
| さらに大きなテキスト | 5 MB 超 | 「大きすぎるため表示しません (サイズ)」 | 同上 |
| UTF-8 でない | UTF-8 として読めない | 不正なバイトは置き換えて表示し、「UTF-8 ではない」と出す | |
| シンボリックリンク | `lstat` | 中を指すリンクはリンク先を表示する。外を指すリンクはリンク先のパスだけを出す ([security.md](security.md)) | git のとおり (リンク先の文字列の差分) |

- 画像などの生のバイト列は `GET …/raw` で返す (50 MB まで)。コミットの版は `rev` を付けて `git cat-file` で読む
- 画像のファイルのタブは、開いたときに全体が枠に収まる倍率で中央に置く。元の大きさより大きくはしない (小さなアイコンなどは 100%)。元の大きさが分からない画像は拡大・縮小せず、そのまま中央に出す

### 5.2 拡大・縮小の表示

Markdown の図と画像のモーダル (§5) と、画像のファイルのタブ (§5.1) で同じ (`web/src/components/viewers/zoom-dialog.tsx`)。

- ホイールでカーソルの位置を中心に拡大・縮小、ドラッグで移動、ダブルクリックで全体の表示に戻す
- 上の帯のボタンとキー: 縮小 (`-`)、倍率の表示 (押すと等倍。キーは `1`)、拡大 (`+`)、全体 (`0`)。ボタンとキーは 1 回で 1.25 倍ずつ変える
  - モーダルでは、開いているあいだキーを受ける。画像のタブでは、表示をクリックしてフォーカスがあるときだけ受ける (検索欄などへの入力で拡大・縮小しないため)
- 倍率は元の大きさの 5%〜2000%。300% 以上では、画像を補間せずに画素のまま拡大する
- 拡大・縮小や移動をしていないあいだは、枠の大きさが変わると (グループの幅を変えたときなど) 全体の表示に合わせ直す
