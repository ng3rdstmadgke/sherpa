# 検索

[overview.md](overview.md) から分けた、ファイルメニューの検索。実装は `web/src/server/search.ts` (サーバー) と `web/src/components/workspace/side-panels.tsx` (画面)。

## 1. 画面

```
/Contents\ /File\
┌──────────────────────────┐
│ 🔍 内容で絞り込む  Aa .*    │
└──────────────────────────┘
┌──────────────────────────┐
│ 対象: *.md, docs/adr      │
└──────────────────────────┘
┌──────────────────────────┐
│ 対象外: tmp, *.log        │
└──────────────────────────┘
```

- ファイルメニューのサイドパネルの一番上に置く。「Contents」(内容) と「File」(ファイル名) をタブで切り替え、検索語と条件はタブごとに別々に持つ
- 検索すると、エクスプローラのツリーを、ヒットしたファイルとその親のディレクトリだけに絞り込む (別の結果一覧は出さない)。SPEC は絞り込まない
- 検索するのは、そのタブで開いている worktree だけ
- `Aa` (大文字小文字を区別)・`.*` (正規表現) で条件を切り替える。ON のものは枠と背景で示す
  - 正規表現が正しくないときは、検索欄の下に「正規表現が正しくありません」と出し、絞り込まない
- 「対象」「対象外」: カンマ区切りの glob。`/` を含まないもの (`*.md`、`tmp`) はどの階層にも当てはまり、ディレクトリを書いたらその下すべてに当てはまる (VS Code と同じ)。パスのサジェストを付ける
- エクスプローラの「変更のみ」「.md のみ」「gitignore」と組み合わせられる。「gitignore」が ON なら無視されたファイルも探す
- 内容の検索では、ファイルの行にヒット数を出し、その下にヒットした行を並べて、一致した部分を強調する。ファイルの行をクリックするとファイルを開き、ヒットした行をクリックするとその行へスクロールして強調する
- ファイル名の検索は、worktree の直下からのパス (`src/lib/search.ts`) に当てる。`lib/se` のようにディレクトリを含めても探せる
  - 一致した部分のうち、ファイル名の中にある部分を強調する (ディレクトリの行は強調しない)
- エクスプローラの上に件数 (`7 件 / 4 ファイル`) を出す。多すぎて打ち切ったときは「(多いため一部だけ)」を添える
- 検索を消すと (`Esc` か ×)、元の開閉の状態に戻る
- `Ctrl+G` で Contents、`Ctrl+P` で File の検索欄にフォーカスする (ファイルメニューに切り替えてから)
- 入力から 200 ms 待ってから問い合わせる。古い問い合わせは止める

## 2. 検索語の解釈

`web/src/lib/search.ts` の `buildMatcher` がブラウザとサーバーで共通の解釈を持つ。

- 正規表現 OFF: 文字どおりに探す
- 大文字小文字の区別 OFF: 大文字小文字を区別しない

## 3. 内容の検索 (`GET …/search/content`)

- worktree の直下で `rg --json --line-number --no-config --hidden --engine auto -e <検索語> .` を実行する
  - 大文字小文字の区別 ON は `-s`、OFF は `-i`。正規表現 OFF は `-F`
  - `--engine auto`: 後読み・後方参照など Rust の正規表現にないものは PCRE2 で扱う (ブラウザの正規表現に近づけるため)。それでも rg が受け付けないものは `INVALID_REGEX`
  - 「gitignore」OFF は rg の既定 (`.gitignore` を守る)、ON は `--no-ignore`。`--hidden` は常に付ける (管理下のドットファイルも探すため)
  - 除外パターン・別の worktree は `-g !<パターン>`、「対象」「対象外」は `-g <パターン>` / `-g !<パターン>` で渡し、結果を `matchesAny` でもう一度絞る (正は `glob.ts`。[files.md](files.md) §3)
  - 上限: 1 ファイルに 100 件 (`--max-count`)、2 MB を超えるファイルは読まない (`--max-filesize`)、1 行は 1,000 文字 (`--max-columns` と `--max-columns-preview`)、全体で 2,000 件 (超えたら rg を止めて `truncated`)。20 秒で止める
- `submatches` の `start` / `end` は UTF-8 のバイト位置なので、行の文字列の UTF-16 の位置に変換して返す
- rg の出力は、複数バイトの文字が chunk の境目で切れても壊れないよう `StringDecoder` で読む
- 結果はパスと行の順に並べる

## 4. ファイル名の検索

- 「gitignore」OFF: エクスプローラの一覧はブラウザにあるので、ブラウザで `buildMatcher` をパスに当てて絞る (入力のたびにサーバーに問い合わせない)
- 「gitignore」ON: 無視されたディレクトリの中身はブラウザにないので、`GET …/search/files` でサーバーに問い合わせる
  - `rg --files --no-config --hidden --no-ignore .` の一覧に、除外パターン・対象・対象外と `buildMatcher` (パスに当てる) を当てる。5,000 件で打ち切る
  - 管理下・Untracked 以外のものに `ignored` を付けて返し、ブラウザでツリーに差し込む (lazy のディレクトリの中でも出る)
- あいまい一致はしない

## 5. rg の実行ファイル

- npm の `@vscode/ripgrep` に同梱のものを使う (`node_modules/@vscode/ripgrep-<platform>-<arch>/bin/rg`)。環境変数 `SHERPA_RG` があればそれを使う
- パッケージを import すると、Turbopack が rg の実行ファイルまでバンドルしようとして失敗するので、パスを直接組み立てる (`web/src/server/exec.ts` の `rgPath()`)
- 見つからなければ `RG_NOT_FOUND`。内容の検索とファイル名の検索 (gitignore ON) が使えない
