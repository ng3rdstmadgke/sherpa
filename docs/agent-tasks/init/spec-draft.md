# sherpa 仕様ドラフト (v4 / 本実装)

> **初回の実装のときの資料 (更新しない)**。最新の仕様と仕組みは `docs/architecture/overview.md`、開発の手順は `docs/how-to/development/` にある。

複数のプロジェクトのソースコード・Markdown・git 差分を、1 つのローカル Web アプリで横断して閲覧するツール。
**閲覧専用**で、編集や git の操作 (add / commit など)、tmux との連携は範囲外とする。AI の操作やコマンドの実行は引き続き tmux で行う。

本実装: `web/` (サーバーの API で fs・git・rg から読む。保存は SQLite)。モック (ダミーデータ) は公開していない。
本実装の計画と、仕様どおりにできなかった点 (未決事項): `docs/agent-tasks/init/implementation-plan.md`。

## 1. 解決したい課題

| 課題 | sherpa での解決 |
| --- | --- |
| プロジェクトごとに VS Code を開くのが手間 | 登録したプロジェクトをブラウザのタブで切り替える |
| devcontainer へのアタッチが遅い | ホスト側のファイルを直接読むため、コンテナは不要 |
| worktree の階層が深い | worktree ごとにタブを開く。1 階層しかないディレクトリはまとめて 1 行で表示する |
| worktree で並列に作業している | 同じプロジェクトを、worktree 別に複数のタブで開ける |
| AI が書いた spec を探すのが手間 | ファイルメニューの SPEC セクション (置き場所を worktree ごとに指定)、検索、自動更新 |

## 2. 決定事項

| 項目 | 決定 |
| --- | --- |
| DB | SQLite |
| アクセス | 開発サーバー (Linux) で起動し、`127.0.0.1:4747` でのみ待ち受ける (3000 番は他のツールでよく使うため避ける)。ローカルマシンからは SSH のポートフォワードで開く (README 参照)。認証は設けない |
| 検索の範囲 | そのタブの worktree だけ (全プロジェクト・全ワークツリーの横断は不要)。検索結果は別の一覧にせず、エクスプローラを絞り込んで表示する |
| 差分の比較対象 | 「未コミットの差分」と「COMPARE (任意のブランチとの比較)」に分ける。比較対象のブランチは worktree バーで選び、タブ全体 (Git メニュー・エクスプローラ・比較対象との差) で共通にする。COMPARE の既定は `main`。`master` や `develop` なども選べる |
| ファイルの自動再読み込み | する。AI などがファイルを書き換えたら、開いているタブと差分を自動で更新する |
| 閲覧以外の操作 | 範囲外 |
| tmux との連携 | 不要 |
| worktree の切り替え | タブの中で切り替える。別の worktree を並べて見たいときは、新しいタブで開く |
| 同じ worktree をもう一度開いたとき | 新しいタブは作らず、すでに開いているタブに移る |
| 再起動したときの状態 | 開いていたタブ (設定タブを含む)、選択中のタブ、メニュー、分割レイアウト、各タブの差分の表示状態、比較対象、SPEC 欄の入力、サイドパネルの縦幅、ライト / ダークのテーマを復元する (§4.3) |
| 最近更新されたドキュメント | メニューごと不要 |
| COMPARE の既定ブランチ | `main` → `master` → `develop` の順に、最初に見つかったローカルのブランチを使う。ローカルになければ、リモートの同じ名前 (`upstream/main` など。リモートの名前は決め打ちしない) を使う。プロジェクトの設定で上書きできる |
| `git fetch` | sherpa からは実行しない (閲覧専用)。リモートのブランチは、ユーザーが最後に fetch した時点の状態を表示する |

## 3. 画面構成

```
┌ sherpa ─ [Projects] [● webapp ×] [● webapp / 33_new_region ×] [● infra ×] [⚙ 設定 ×] [+] ─ ☾ ⚙ ┐
├ [⎇ worktree ▼] [比較: main +未コミット ▼] [📄 SPEC: agent-tasks/…/*  4 件] (i)                      ⟳• ┤
│📄│ /Contents\ /File\    │ [spec.md ×][regions.ts ×]  ◫ ⊟ × │ [overview.md (main) ×]    ◫ ⊟ × │
│⎇ │ [🔍 検索  Aa ab .*]  │ regions.ts  [Unified|Split]        │ overview.md  [Unified|Split]     │
│  │ ▾ SPEC (4)           │             [差分を閉じる]         │              [ファイル全体]      │
│  │ ▾ EXPLORER           │  (エディタグループ 1)              │  (エディタグループ 2)            │
│  │  [変更][.md][gitignore] │                                 │                                  │
└──┴──────────────────────┴────────────────────────────────────┴──────────────────────────────────┘
```

### 3.1 一番上のタブ (プロジェクトタブ)

- 1 つのタブが「プロジェクト + worktree」に対応する。同じプロジェクトを複数のタブで開ける
- ラベルは、main worktree なら `プロジェクト名`、それ以外なら `プロジェクト名 / worktree 名`
- `+` メニューにはプロジェクトごとに worktree の一覧が並び、選んだ worktree を新しいタブで開く
  - 同じプロジェクトと worktree の組がすでに開いていれば、そのタブに移る
- タブの中で worktree を切り替えると、ラベルも切り替わる
- × か中クリックで閉じる
- プロジェクトのタブの後ろに、全体の設定のタブ (§3.3) が並ぶ
- 右上に、ライト / ダークの切り替え (☾) と、全体の設定 (⚙) のボタンを置く
  - 選んだテーマは保存し、次に開いたときも同じテーマにする。読み込み直後にライトで一瞬表示されないよう、ページの最初で保存済みのテーマを反映する
  - テーマを切り替えると、表示中の mermaid の図もそのテーマで描き直す

### 3.2 ホーム (Projects)

- 登録済みのプロジェクトをカードで表示する。カードには worktree ごとのブランチ、ahead / behind、未コミットのファイル数を出す
  - ahead / behind は、プロジェクトの既定の比較対象のブランチに対する値 (worktree の選択と `+` メニューも同じ)。上流ブランチ (`@{u}`) は使わない (fetch しないうえ、上流のない worktree が多い)
  - ブランチにない HEAD は `(detached) <短いハッシュ>` と出す。ディレクトリが消えた worktree は薄く「見つかりません」と出し、開けないようにする
- worktree の行をクリックすると、その worktree をタブで開く
- **プロジェクトの登録・編集** (同じダイアログを使う)
  - 登録: ホームの「プロジェクトを登録」ボタン
  - 編集: カードの「…」メニューの「編集」、またはタブの中の (i) 詳細の「プロジェクトの設定」
  - 項目
    - ディレクトリのパス (編集では変更できない)、表示名
    - devcontainer のパスマッピング。自動で検出する (§4.1)
    - 表示しないパス (除外パターン): 全体の設定の値に追加するパターン (§3.7.1)。全体の設定の値はここには並べず、「全体の設定を開く」のリンクを置く (ダイアログを閉じて、設定タブの除外パターンの項目を開く)
    - 既定の比較対象のブランチ: 「自動」かブランチの一覧 (ローカル / リモート) から選ぶ。自動なら `main` → `master` → `develop` の順に、最初に見つかったローカルのブランチを使い、実際に使うブランチを横に表示する (§2)。プロジェクトのタブを新しく開いたときの比較対象になる
  - 「ディレクトリ」「ホスト」「表示しないパス」には、パスのサジェストを付ける (§3.4)。「ディレクトリ」の候補では、git リポジトリと登録済みのものに印を付ける
  - 登録では、「ディレクトリ」の末尾の `/` を取り除いて保存する
- **プロジェクトの登録の解除**: カードの「…」メニューの「登録を解除」。確認のダイアログを出す
  - sherpa に保存したもの (プロジェクトの設定、パスマッピング、SPEC 欄の入力) だけを消す。リポジトリのファイルには触れない
  - そのプロジェクトのタブはすべて閉じる
- カードは登録した順に並べる (一番上のタブの `+` メニューも同じ)。並べ替えはしない

### 3.3 全体の設定

- 右上の歯車のボタンで、一番上のタブの並びに「⚙ 設定」タブを開く (ダイアログではなく専用のページ)。すべてのプロジェクトに適用する
  - 設定タブは 1 つだけ。開いていればそこへ移る。× か中クリックで閉じる。開いているかどうかは保存する
  - 今後設定が増えることを想定し、左に項目の一覧 (グループ分け)、右に内容を並べる。項目の一覧をクリックすると、その項目までスクロールする
  - 他の画面から項目を指定して開いたときは、その項目までスクロールして枠で強調する
- 項目
  - 表示・検索 › 除外パターン: §3.7.1

### 3.4 パス入力のサジェスト

次の入力欄では、入力中にパスの候補を出す。

| 入力欄 | 候補 | 複数指定 | ディレクトリの直後に出す候補 |
| --- | --- | --- | --- |
| プロジェクトの登録・編集の「ディレクトリ」 | サーバーのディレクトリ (ディレクトリのみ。git リポジトリに「git」、登録済みに「登録済み」の印) | - | - |
| devcontainer パスマッピングの「ホスト」 | 同上 | - | - |
| プロジェクトの登録・編集の「表示しないパス」 | worktree の中のファイルとディレクトリ (`.gitignore` の対象に「gitignore」の印) | 1 行に 1 つ | `dir/**` (その下すべて) |
| worktree バーの SPEC 欄 | 同上 | カンマ区切り | `dir/*` (その下すべて) |
| ファイルメニューの検索の「対象」「対象外」 | 同上 | カンマ区切り | - |

- 入力中のパスの最後の `/` までをディレクトリとし、その中身のうち続く文字で始まるものを出す (シェルの補完と同じ)。ディレクトリを選ぶと、続けてその中身を出す
- 複数指定の欄では、カーソルのある項目だけを補完する
- `Tab`: 選択中 (なければ先頭) の候補で補完する。`↑` `↓`: 候補を選ぶ。`Esc`: 候補を閉じる
- `Enter` は `↑` `↓` で候補を選んでいるときだけ補完に使う。それ以外は元の動作 (SPEC 欄の確定、除外パターンの改行) のまま
- `*` を含む項目では候補を出さない
- 「ホスト」は編集できる。手で書き換えるまでは「ディレクトリ」と同じ値にする
- 本実装では、ディレクトリの中身を返す API をサーバーに用意する (ホーム以下、または worktree の中に限る)
  - ホーム以下はディレクトリの名前だけを返す。「git」の印は `.git/HEAD` (または `gitdir:` の書かれた `.git` ファイル) があるときに付ける

### 3.5 worktree バー

一番上のタブの下に置く。表示するのは次の 3 つと、(i) 詳細・再読み込みのボタンだけにする。

```
[⎇ 33_new_region ▼] [比較: main +未コミット ▼] [📄 SPEC: agent-tasks/226_add_gateway/*   2 件] (i)   ⟳•
```

- **ワークツリーの選択**: タブの中で worktree を切り替える
- **比較対象の選択**: §3.5.1
- **SPEC 欄**: ファイルメニューの SPEC に出すドキュメントの場所を入力する
  - カンマ区切りで複数指定できる (例: `.ai/agent-tasks/226_add_gateway/*, agent-tasks/226_add_gateway/*`)
  - 末尾の `/*` と、ワイルドカードのないディレクトリの指定は、その下の階層すべてを対象にする。`**` と `*` の glob も使える
  - spec の場所はブランチ (worktree) ごとに違い、ブランチ名から決まるとは限らないため、worktree ごとに手で指定して保存する
  - `Enter` かフォーカスが外れたときに確定し、`Esc` で入力前に戻す。右に、見つかった `.md` の件数を表示する
- **(i) 詳細**: クリックするとポップオーバーで次を表示する。ブランチ名・ディレクトリ・コンテナ内のパスにはコピーボタンを付ける (パスは省略せずに折り返す)
  - ブランチ名
  - ディレクトリ (ホスト側のパス)
  - コンテナ内のパス (devcontainer のパスを読み替えている場合だけ。§4.1)
  - 比較対象との差 (↑ 先行 / ↓ 遅れのコミット数)
  - 最新のコミット
  - 下部に「プロジェクトの設定」(編集ダイアログを開く)
- 右端に再読み込みボタンを置く。自動更新 (ファイルの監視) 中であることを、ボタンの緑の点で示す

#### 3.5.1 比較対象

- worktree バーに「比較: main ▼」のプルダウンを置き、差分の比較対象をタブ (worktree) ごとに選ぶ。選んだ値は保存する
  - ブランチは検索できる一覧から選ぶ。ローカルとリモートに分けて並べる。既定は `main` (§2 の決定事項)
  - プルダウンの中に「未コミットの変更を含む」(既定 ON) を置く。ON なら比較範囲は `<branch>...作業ツリー`、OFF なら `<branch>...HEAD`
- 比較対象はタブ全体の設定で、次のすべてが参照する
  - Git メニューの COMPARE と HISTORY
  - エクスプローラの「変更のみ」と、ファイル名の横の記号 (M / A など)
  - ファイル表示の「差分を見る」
  - worktree バーの詳細 (i) の「比較対象との差」(比較対象のブランチに対して何コミット先行 / 遅れているか)

### 3.6 メニュー (左端のアイコン列)

| メニュー | サイドパネル | 中央 |
| --- | --- | --- |
| ファイル (`Ctrl+Shift+E`) | 検索 / SPEC / エクスプローラ | ファイル用のエディタ領域 |
| Git 差分 (`Ctrl+Shift+G`) | 未コミットの差分 / COMPARE / HISTORY | Git 用のエディタ領域 |

- **中央のエディタ領域 (タブと分割の状態) は、メニューごとに独立して持つ**。メニューを切り替えると、中央の表示もそのメニューのものに切り替わる
- メニューを切り替えても、それぞれのタブ、分割の状態、スクロール位置は残る

### 3.7 ファイルメニュー

サイドパネルは、上から「検索欄」「SPEC」「EXPLORER」の順に並べる。
SPEC と EXPLORER は Git メニューと同じく、境界線のドラッグで縦幅を変えられ、見出しのクリックで折りたためる (配分は保存する)。

```
 [🔍 内容で絞り込む      ]
 [内容|ファイル名]
 ▾ SPEC (4)
     ▾ agent-tasks/feature/33_new_region
         spec.md
         plan.md
     ▾ docs/superpowers …
 ───────────────────
 ▾ EXPLORER            [変更のみ][.md のみ][gitignore]
     ▸ .devcontainer
     ▸ app …
```

- **検索** (パネルの一番上に置く)
  - 「Contents」(内容) と「File」(ファイル名) をタブで切り替える。検索語と条件はタブごとに別々に持つ

    ```
    /Contents\ /File\
    ┌──────────────────────────┐
    │ 🔍 内容で絞り込む  Aa ab .* │
    └──────────────────────────┘
    ┌──────────────────────────┐
    │ 対象: *.md, docs/adr      │
    └──────────────────────────┘
    ┌──────────────────────────┐
    │ 対象外: tmp, *.log        │
    └──────────────────────────┘
    ```

  - 検索すると、**エクスプローラのツリーを、ヒットしたファイルとその親のディレクトリだけに絞り込む** (別の結果一覧は出さない)。**SPEC は絞り込まない**
  - 検索語の横の `Aa` (大文字小文字を区別)・`ab` (単語単位)・`.*` (正規表現) で条件を切り替える。ON のものは枠と背景で示す
    - 単語単位は、前後が文字・数字・`_` でないときだけ一致する (日本語の文字も単語の一部として扱う)
    - 正規表現が正しくないときは、検索欄の下に「正規表現が正しくありません」と出し、絞り込まない
  - 「対象」「対象外」: カンマ区切りの glob。`/` を含まないもの (`*.md`、`tmp`) はどの階層にも当てはまり、ディレクトリを書いたらその下すべてに当てはまる (VS Code と同じ)。パスのサジェスト (§3.4) を付ける
  - 検索するのは、常にそのタブで開いている worktree だけ (他の worktree や他のプロジェクトは対象外)
  - エクスプローラの「変更のみ」「.md のみ」「gitignore」と組み合わせられる。差分のあるファイルだけを検索したいときは「変更のみ」を使う
  - 内容の検索では、ファイルの行にヒット数を出し、その下にヒットした行を並べる。一致した部分を強調する
    - ファイルの行をクリックするとファイルを開く。ヒットした行をクリックすると、その行へスクロールし、行を強調して表示する
  - ファイル名の検索では、ファイル名の中の一致した部分を強調する
  - 絞り込んでいる間はディレクトリをすべて開いて表示する。検索を消すと (`Esc` か ×)、元の開閉の状態に戻る
  - エクスプローラの上に件数 (`7 件 / 4 ファイル`) を表示する
  - `Ctrl+B` で Contents、`Ctrl+P` で File の検索欄にフォーカスする (ファイルメニューに切り替えてから)
  - ファイル名で探すための専用のダイアログは設けない (この検索欄で足りるため)
- **SPEC**
  - AI が作る設計資料 (spec / plan など) を、エクスプローラの上に常に表示する。表示はツリーだけ
  - worktree バーの SPEC 欄 (§3.5) で指定した場所にある `.md` を出す。`.gitignore` で無視されていても出す (除外パターンに当たるものは出さない)
  - SPEC 欄が空のときは、入力を促す案内を出す
  - AI の作業ファイルは git の管理外なので、Git メニューの差分やエクスプローラの「変更のみ」には出ない。差分を見る機能は今は作らない (将来、sherpa が自分で版を保存して差分を出す案がある)
- **エクスプローラ**
  - ツリー表示。**比較対象 (§3.5.1) との差分の状態** (M / A / U / D) を色と記号で表示する
  - 子が 1 つしかないディレクトリは連結して表示する
  - `.gitignore` で無視されたファイルは表示しない
  - 見出しの右の「変更のみ」「.md のみ」「gitignore」で絞り込む (組み合わせられる)
    - 「変更のみ」: 比較対象との差分があるファイルだけを残す (Git メニューの COMPARE に出るファイルと一致する)
    - 「gitignore」: ON にすると、`.gitignore` で無視されたファイルも薄い色で表示する。検索の対象にも含める
- **ツリーの右クリックメニュー** (SPEC・エクスプローラ・Git メニューの未コミットの差分 / COMPARE のツリーで共通)
  - ディレクトリかファイルの行を右クリックすると、メニューを出す。右クリックした行は枠で示す
  - 「相対パスをコピー」: worktree の直下からのパス (例: `app/src/config/regions.ts`) をクリップボードにコピーし、画面の右下に「コピーしました」と短く表示する
  - 連結して 1 行で表示しているディレクトリ (`agent-tasks/feature/33_new_region`) は、その行が表す一番深いディレクトリのパスをコピーする
  - 行以外の場所を右クリックしたときは、ブラウザ標準のメニューを出す
  - メニューはツリー全体で 1 つだけ持つ (行が数千あっても重くならないように)

#### 3.7.1 表示・検索の対象

- **表示しないパス (除外パターン)**: エクスプローラ・SPEC・検索のどれにも出さない。「gitignore」を ON にしても出さない。`.gitignore` の書き漏れを補い、大量のファイルでツリーが重くなるのを防ぐ
  - 全体の設定 (§3.3) の値に、プロジェクトの設定の値を追加したものを使う
  - 全体の設定の初期値: `**/node_modules/**`, `**/__pycache__/**`, `**/*.pyc`, `**/.venv/**`, `**/.terraform/**`, `**/.git/**`
  - プロジェクトの設定の例: toolbox の `tmp/backup/**`、webapp の `archives/**`
- **SPEC に出す場所**: worktree バーの SPEC 欄 (§3.5) で、worktree ごとに指定する
- パターンは worktree の直下から数える glob (`**` と `*`)
- worktree の中にある別の worktree (`.worktree/<name>` など) は、常に表示しない (別のタブで開くため)
- 実装では、ファイルの一覧は `git ls-files --cached --others --exclude-standard` (「gitignore」が ON なら `--others --ignored --directory` の分も)、検索は ripgrep で取り、同じ除外パターンで絞り込む
  - 「gitignore」ON のとき、無視されたディレクトリ (`node_modules/` など) は `--directory` で 1 行にまとめ、開いたときに中身を読む (toolbox では無視されたファイルが 12 万件ある)
  - 除外パターンは、列挙の時点で git の pathspec (`:(exclude,glob)…`) と rg の `-g !…` にも渡し、余計なファイルを列挙させない。最後に `web/src/lib/glob.ts` で絞り込み、その結果を正とする

### 3.8 エディタ領域 (画面分割)

- VS Code のエディタグループに相当する。グループ (タブの束) を左右・上下に、入れ子で分割できる
- **ドラッグ & ドロップ**
  - ドラッグできるもの: タブ、SPEC・エクスプローラのファイル (検索で絞り込んだものを含む)、Git メニューの変更ファイルとコミット
  - グループの本文の端 (上下左右の 25%) にドロップすると、その方向に分割して新しいグループで開く
  - 中央かタブバーにドロップすると、そのグループに移る
  - ドラッグ中は、ドロップ先の領域をハイライト表示する
- タブバーの右端に「右に分割」「下に分割」「グループを閉じる」のボタンを置く
- 最後のタブを閉じたグループは自動で消える (最後の 1 グループは残す)
- 分割の境界線はドラッグしてサイズを変えられる

#### 3.8.1 グループ内検索 (Ctrl+F)

- 中央の表示で `Ctrl+F` を押すと、選択中のグループの右上に検索バーを出す (VS Code と同じ)
  - 検索範囲は、選択中のグループで表示しているタブの本文だけ。サイドバーや他のグループは含めない
  - 対象はコード、Markdown のプレビュー (表示されている文章)、差分、コミットの詳細
  - 差分の行番号と `+` / `-` の記号は対象外。mermaid の図 (SVG) の中の文字も対象外
- 操作: `Enter` で次へ、`Shift+Enter` で前へ、`Esc` で閉じる。大文字小文字の区別を切り替えられる。件数 (`3/12`) を表示する
- 文字列を選択してから `Ctrl+F` を押すと、それを検索語にする
- 検索バーを開いたままタブを切り替えると、切り替えた先のタブで検索し直す
- 検索欄にフォーカスがある状態でもう一度 `Ctrl+F` を押すと、ブラウザ標準の検索を開く
- 強調には CSS Custom Highlight API を使う (DOM を書き換えない)

### 3.9 ファイル表示

- **Markdown**
  - GFM (表、タスクリスト)、mermaid、画像 (相対パス) に対応する
  - 相対リンクは、そのファイルのディレクトリを基準に解決して、アプリ内のタブで開く (`./plan.md`、`../../docs/adr/…`。`/` で始まるものは worktree の直下から。`#見出し` は取り除く)
  - プレビューとソースを切り替えられる
- **コード**: シンタックスハイライト (shiki)、行番号
- パンくずリストの横のボタンで、相対パスをコピーする (コピーしたらアイコンを ✓ に変える)
- 比較対象 (§3.5.1) との差分があるファイルには「差分を見る (main)」ボタンを出す
  - 押すと、**同じタブの中で、ファイル全体に差分を重ねて表示する** (新しいタブや画面の分割はしない)。ファイル全体のどこが変わったのかが分かるよう、変更のない行も省略しない
  - Unified / Split を切り替えられる。Split も同じタブの中で左右に並べる
  - 「差分を閉じる」で通常の表示に戻る。差分を表示しているか、どちらの形式かはタブごとに保存する

### 3.10 Git 差分メニュー

サイドパネルは、次の 3 つのセクションで構成する。

- セクションの境界線をドラッグすると、各セクションの縦幅を変えられる。中身があふれたら、セクションの中でスクロールする
- 見出しをクリックすると、見出しだけの高さに折りたたむ。空いた分は隣のセクションに回す。境界線を見出しの高さまでドラッグしても折りたためる
- 縦幅の配分と折りたたみの状態は保存し、次に開いたときに復元する (すべてのタブで共通)

```
▾ 未コミットの差分 (3)                 HEAD...作業ツリー
    ▾ app/
      ▾ src/
        ▾ config/
            regions.ts        +9 -1  M
    ▾ docs/
      ▾ architecture/
            overview.md       +10 -2 M
▾ COMPARE (6)                     main...作業ツリー
    ▾ app/ …  (ツリー)
▾ HISTORY (4)                            main..HEAD
    ref #33 設計判断をADRに記録する
    2ff64ad · Claude · 2時間前 · 2 files
```

- **未コミットの差分**: `git diff HEAD` (Staged と Unstaged をまとめる。Untracked も含む)。ツリーで表示する
- **COMPARE**: 比較対象 (§3.5.1) との差分。ツリーで表示する。見出しに比較範囲 (`main...作業ツリー`) を出す
  - 比較対象は worktree バーで選ぶ。このセクションには選択欄を置かない
  - 比較範囲はマージベースとの比較 (`<branch>...`)
- **HISTORY**: `git log <branch>..HEAD`。比較対象のブランチにないコミットだけを表示する
  - クリックするとコミットの詳細を開く。変更ファイルはアコーディオンで表示し、クリックするとその場で差分を展開する (別のタブは開かない)。差分の変更のない部分は、差分のタブと同じく「N 行を表示」にまとめる
  - 「すべて展開」「すべて折りたたむ」、Unified / Split の切り替え
- ツリーの変更ファイルをクリックすると、Git 用のエディタ領域に差分のタブを開く
  - 同じファイルでも比較元が違えば別のタブになる。タブ名は `regions.ts (未コミット)`、`regions.ts (main)` のようにする
  - 差分は Unified / Split を切り替えられる。Markdown は、左に差分・右に変更後のプレビューを並べて表示できる
  - 変更のない部分は、変更の前後 3 行だけを残して「N 行を表示」の行にまとめる。クリックすると、その部分を展開する
  - 差分のタブの中で「差分」と「ファイル全体」を 1 つのボタンで切り替える (押すたびに入れ替わる。ボタンには切り替え先を表示する。新しいタブは開かない)。ファイル全体では、Markdown はプレビューとソースを切り替えられる
  - どちらを表示しているかはタブごとに保存し、タブを切り替えたり再起動したりしても残る
- ファイル表示の「差分を見る」は、**比較対象との差分**を同じタブの中に表示する (§3.9)
- 左端のアイコンのバッジには、未コミットのファイル数を出す
- ツリーの行の右側に、追加・削除の行数 (`+9 -1`) と状態 (M / A / U / D) を出す。行数は比較対象との実際の差分から数える

### 3.11 自動更新

- worktree のファイルを監視し、変更があれば、開いているタブ、差分、ツリー、git の状態を自動で再読み込みする
- 再読み込みしたときは、画面の右下に小さく通知する
  - 通知は、開いているタブ (ファイル・差分) を読み直したときだけ出す。ツリーや件数だけが変わったときは出さない
- worktree バーの右端に手動の再読み込みボタンを置き、監視中であることをボタンの緑の点で示す
  - サーバーとの接続 (SSE) が切れているときや、監視できないとき (inotify の上限など) は、点を灰色にする
- 監視するのは、ブラウザのタブで開いている worktree だけ。除外パターン・別の worktree・`.gitignore` で無視されたディレクトリは監視しない。ただし、SPEC の場所と開いているファイルの場所は、無視されていても監視する

## 4. 技術的な論点

### 4.1 devcontainer のパスの読み替え (必須)

worktree はコンテナの中で作られるので、`.git` ファイルにコンテナ内のパスが記録されている。

```
~/webapp/.worktree/33_new_region/.git
  → gitdir: /workspaces/webapp/.git/worktrees/33_new_region
```

そのため、ホストで `git status` を実行すると `fatal: not a git repository` で失敗する。
`GIT_DIR` と `GIT_WORK_TREE` を明示すると動くことを確認した (`commondir` は相対パスの `../..` なので問題ない)。

```bash
GIT_DIR=~/webapp/.git/worktrees/33_new_region \
GIT_WORK_TREE=~/webapp/.worktree/33_new_region git status
```

- 「コンテナ内パス → ホストのパス」の対応表をプロジェクトごとに持ち、git を実行するときに環境変数で渡す
  - `GIT_DIR` と `GIT_WORK_TREE` は、main worktree も含めて常に 2 つとも渡す (`GIT_DIR` だけだと、実行したディレクトリが worktree の直下とみなされる)
- worktree の一覧は `git worktree list` を使わずに `.git/worktrees/*/gitdir` を読み、パスを読み替えて作る (git は `prunable` と誤判定するため)
  - 読み替えたパスに `.git` ファイルがあり、それが `.git/worktrees/<id>` を指しているときだけ有効とする (開発サーバーには `/workspaces/...` の空のディレクトリがあるので、ディレクトリがあるだけでは判断しない)
  - `<id>` と worktree のディレクトリ名は一致するとは限らない (例: `.git/worktrees/25_hardening` → `.worktree/25_hardening_phase01`)。worktree の識別には `<id>`、表示にはディレクトリ名を使う
  - ホストの git から見るとこれらの worktree は `prunable` なので、`git worktree prune` や `git gc` が走ると管理用のディレクトリが消える。sherpa は gc を起こさない (`-c gc.auto=0` を付ける)
- 対応表の既定値は `devcontainer.json` の `workspaceFolder` から作る。未指定なら、worktree の `.git` ファイルに記録されているパス (`gitdir: <X>/.git/worktrees/<id>` の `<X>`)、それもなければ `/workspaces/<ディレクトリ名>`

### 4.2 アーキテクチャ

- Next.js の Route Handler から、`fs`・`git` CLI・`rg` (ripgrep) を呼ぶ
  - 全文検索は ripgrep で十分に速いので、インデックスは作らない。Go / Rust は当面使わない
  - ファイル名検索は、あいまい一致にせず、内容の検索と同じ条件 (`Aa` / `ab` / `.*`) で絞る (モックと同じ)。「gitignore」OFF ならブラウザにあるエクスプローラの一覧で絞り、ON なら無視されたファイルも含めてサーバーで絞る
  - rg は開発サーバーに入っていないので、npm の `@vscode/ripgrep` に同梱のものを使う。見つからなければ、内容の検索だけを使えなくする
  - 正規表現は `--engine auto` で渡し、後読みなど Rust の正規表現にないものは PCRE2 で扱う (ブラウザの正規表現に近づけるため)
- ファイルの監視は chokidar などで行い、SSE でブラウザに通知する
  - `.git` の HEAD や index の変化も監視し、git の状態を更新する
- ファイルの読み取りは、登録したプロジェクトの配下 (と、その worktree) だけに許可リストで制限する
  - パスは worktree の直下からの相対パスで受け取り、`..` や絶対パスを断る。`realpath` でシンボリックリンクを解決した結果も worktree の中にあることを確かめる。worktree の外を指すシンボリックリンクは、リンク先のパスだけを表示する
  - 例外として、パス入力のサジェスト (§3.4) の API は、プロジェクトの登録のためにホーム以下のディレクトリ名だけを返す (ファイルの中身は返さない)
- DNS rebinding と、ほかのサイトからの要求を防ぐ (`web/proxy.ts`)
  - `Host` のホスト名が `127.0.0.1` / `localhost` / `[::1]` のときだけ応答する。ポートは見ない (SSH のポートフォワードで手元の別のポートから開くことがあるため)
  - `Sec-Fetch-Site: cross-site` の要求は断る。書き込み (GET 以外) は、`Origin` が同じホストで、`Content-Type: application/json` のときだけ受け付ける
- 待ち受けは `127.0.0.1:4747` のみ (環境変数 `PORT` で変更できる) (`npm run dev` / `npm run start` で指定済み)

#### 4.2.1 差分の計算

- 差分は、変更のない行も含めてファイル全体を持つ。ファイル全体の中での差分表示と、省略した部分の展開は、この結果を使う
- 比べる版
  - 未コミットの差分: `HEAD` と作業ツリー
  - COMPARE (未コミットを含む): **マージベース** (`git merge-base <branch> HEAD`) と作業ツリー
  - COMPARE (未コミットを含まない): マージベースと `HEAD`
  - コミットの詳細: `<commit>^` (最初の親) と `<commit>`
  - `<branch>` の版そのもの (`git show <branch>:<path>`) とは比べない。比較範囲は `<branch>...` (マージベースから) なので、`<branch>` の側で進んだ変更を差分に混ぜない
- 作り方: `git diff <前> [<後>] -U<大きな値> -- <path>` で全行を含む差分を取り、パースする。git と同じ差分になるので、ツリーの行数 (`--numstat`) と一致する
  - Untracked のファイルは git diff に出ないので、すべて追加の行にする
  - 大きなファイルは前後 3 行だけを取り、省略した部分は展開できないようにする
- モックでは、変更前の内容をダミーデータに持たせ、jsdiff で計算している (`web/src/lib/line-diff.ts`)

### 4.3 永続化 (SQLite)

- 保存するもの
  - 登録したプロジェクト、パスマッピング、プロジェクトごとの除外パターン
  - 全体の設定 (除外パターン)
  - worktree ごとの SPEC 欄の入力
  - UI の状態 (JSON で保存する)
    - 開いているプロジェクトタブ、選択中のタブ、設定タブを開いているかどうか
    - タブごとのメニュー、エディタレイアウト (ファイルタブの差分の表示形式、差分タブの「差分 / ファイル全体」を含む)、比較対象
    - サイドパネル (ファイルメニュー・Git メニュー) のセクションの縦幅と折りたたみ (すべてのタブで共通)
  - ライト / ダークのテーマ
  - モックでは localStorage に保存している (`web/src/lib/persist.ts`)。本実装では同じ関数を SQLite の API に置き換える
    - 最初の描画で値が揃っているよう、ページ (サーバー コンポーネント) が DB から読んで渡す。テーマもサーバーが `<html>` に付けて返すので、読み込み直後にライトで一瞬表示されることはない
  - worktree 自体は保存しない (毎回 `.git/worktrees` から作る)
- ライブラリ: `better-sqlite3` + Drizzle ORM
- DB ファイルの置き場所: `~/.local/share/sherpa/sherpa.db` (環境変数 `SHERPA_DB` で変えられる)
- テーブルの設計: `docs/agent-tasks/init/implementation-plan.md` §7

## 6. モックとの差異

モックで仕様どおりに動かなかった次の点は、本実装ですべて解消した。確認のしかたは `docs/agent-tasks/init/implementation-plan.md` §13。

| 項目 | モックの状態 | 本実装 |
| --- | --- | --- |
| データ | すべてダミー (`mock-data.ts`)。全 worktree で同じファイルツリーを使う | サーバーの API で fs・git・ripgrep から取る。`mock-data.ts` は消した |
| 設定の保存 | 全体の設定とプロジェクトの登録・編集は、「保存」を押しても保存しない | SQLite に保存する (§4.3) |
| プロジェクトの登録の解除 | ない | カードの「…」メニューの「登録を解除」(§3.2) |
| 検索 | ダミーの内容に対して、ブラウザの正規表現で検索する | ripgrep に同じ条件 (`-s` / `-i`・`-w`・`-F`、`-g`) を渡す。ファイル名の検索は、「gitignore」ON のときだけサーバーで探す |
| worktree の中の別の worktree | ダミーのツリーに `.worktree/` がないため確かめていない | 一覧・検索・監視のどれからも外す (§3.7.1)。`.worktree/` のように別の worktree しか入っていないディレクトリも出さない |
| 自動更新 | 表示から 8 秒後に 1 度だけ通知を出すだけ | chokidar と SSE で、変更のたびに再読み込みする。開いているタブを読み直したときだけ通知する (§3.11) |
| 画像 | Markdown の画像は、ファイル名だけを見て `public/mock/` のものを出す | Markdown のあるディレクトリを基準にパスを解決し、サーバーから読む。画像のファイルはタブで画像として、画像の差分は前後を並べて表示する |
| バイナリ・大きなファイル | 扱っていない | バイナリは表示しない。1 MB を超えるものはハイライトせず、5 MB を超えるものは表示しない |
| エラーの表示 | 起きない | git リポジトリでない・worktree が消えた・比較対象のブランチがない・共通の祖先がない・git や rg がないなどを画面に出す |
| 読み込み中の表示 | ない | 各セクションに「読み込み中…」を 1 行出す (レイアウトは変えない) |
| ホームのカードの worktree の場所 | `.worktree/<name>` と決め打ちしている | プロジェクトの直下からの実際のパスを出す |

本実装で、モックと動きが違う点 (仕様の範囲で決めたもの):

- 新しく開いたタブは空で始まる (モックは `spec.md` を開いた状態で始まる)。最初は一番上のタブもない
- エクスプローラの最初の開閉の状態は、すべて閉じている (モックは `app/src/config` を開いている)
- コミットのタブ名は短いハッシュ (7 桁)。HISTORY の件数は、比較対象のブランチにないコミットの数 (500 件を超える分は「ほかに N 件」)
